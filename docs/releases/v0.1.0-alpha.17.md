# Lunetile v0.1.0-alpha.17

변환 후 추가한 **XP 사용자 스크립트**(메시지·이동·오버레이 등)가 실행되도록 호환성을 고칩니다. Windows x86 실험적 릴리스입니다.

## 다운로드

| 파일 | 용도 |
|---|---|
| `lunetile-template-xp-windows-x86.zip` | 새 XP 게임 템플릿, Game.exe와 Lunetile.dll |
| `lunetile-template-vxa-windows-x86.zip` | 새 VX Ace 게임 템플릿, Game.exe와 LunetileVXA.dll |
| `lunetile-template-xp-diagnostics.zip` / `lunetile-template-vxa-diagnostics.zip` | CI 검증·변환 기록·해시 |
| `lunetile-xp-speed-fix.zip` / `lunetile-vxa-speed-fix.zip` | 기존 변환본의 DLL 업데이트. 이전 파일명 유지 |
| `lunetile-vxa-editor-fix.zip` | VX Ace 에디터 저장 후 실행 복구용 파일 |
| `SHA256SUMS.txt` | 배포 ZIP 체크섬 |

각 템플릿을 새 폴더에 풀고 **Game.exe**를 실행하세요. Windows 11 x64, Visual C++ x86 런타임과 해당 엔진의 RTP가 필요합니다. RTP·원본 RGSS DLL·개인 저장/백업/설정은 포함하지 않습니다.

## 변경 사항

- **창·스프라이트 내부 상태 분리 (XP·VX Ace):** `Window`·`Sprite`·`Plane`·`Viewport`·`Tilemap`이 `@x`·`@y`·`@opacity` 같은 인스턴스 변수에 상태를 저장해, 같은 이름을 쓰는 사용자 하위 클래스와 충돌했습니다. 예를 들어 Advanced Message Script(AMS)에서 메시지 글자가 보이지 않고 대화창이 오른쪽으로 밀렸습니다. 원본 RGSS처럼 사용자 코드와 겹치지 않는 내부 이름을 사용합니다.
- **Ruby 1.8 호출 문법 (XP):** `$game_map.valid? (x, y)`처럼 괄호 앞에 공백이 있는 다중 인자 호출은 Ruby 4에서 구문 오류였습니다. 런타임은 구문 오류가 난 줄에서만 공백을 제거해 다시 실행하고 `rgssxp.log`에 기록합니다. `Scripts.rxdata`는 바꾸지 않습니다.
- **사용자 저장 데이터 (XP):** AMS처럼 저장 파일 끝에 자체 Marshal 객체를 추가하는 스크립트에서 수동 저장이 `Trailing XP save data`로 멈췄습니다. 기본 12개 객체 뒤 최대 32개의 완전한 객체를 허용하며, 자동 저장·백업 복구도 같은 규칙을 사용합니다.
- **보정 우회 경고 (XP):** 1280×720·120Hz 프로젝트에서 사용자 스크립트가 보정된 기본 메서드를 별칭 없이 재정의하면 메서드별 경고를 `rgssxp.log`에 남깁니다. 동작은 바꾸지 않습니다.
- **변환기 `--custom-scripts` (XP):** 마지막 기본 스크립트와 `Main` 사이의 사용자 스크립트를 바이트 그대로 유지해 변환합니다. 기본 스크립트는 계속 해시로 검사합니다. 사용자 스크립트는 1280×720·120Hz 자동 보정을 받지 않으므로 `--widescreen`·`--high-refresh`와 함께 쓸 수 없습니다.

## 기존 프로젝트

기존 프로젝트와 `Saves`를 먼저 별도로 보관하세요. 사용자 스크립트를 쓰는 기존 XP 변환본은 `lunetile-xp-speed-fix.zip`의 DLL로 교체하면 위 런타임 수정이 적용됩니다. 기본 스크립트를 직접 수정한 프로젝트는 변환기가 거부합니다. 수정 내용을 별도 사용자 스크립트로 옮긴 뒤 변환하세요.

RPG Maker 에디터에서 변환본을 저장하면 `Game.ini`의 `Library`가 `RGSS104E.dll`로 바뀝니다. 저장 후 `Library=Lunetile.dll`로 되돌리고, 확인은 에디터 테스트 플레이가 아닌 `Game.exe`로 하세요.

## 검증 범위

로컬에서 `verify_runtime.py --mode release`(XP·VX Ace 실제 실행, 저장 재시작·F12·창·브라우저·통신·출력 주기), Python 단위 검사, 사용자 하위 클래스 회귀 검사, XP/VXA 조작·저장·복구 시나리오를 수행했습니다. 제보된 AMS·8방향 이동·오버레이 스크립트 프로젝트에서 부팅, 이동 판정, 메시지 표시, 저장·불러오기·자동 저장 유지를 자동 점검했습니다.

임의의 사용자 스크립트 전체 호환, 사용자 스크립트의 120Hz 진행 속도·1280×720 배치, 실제 플레이 완주는 인증하지 않습니다. AMS의 `\Z[n]`·`\Color[n]`·`\T[...]`는 원본 RGSS에서도 `string modified` 오류가 나는 스크립트 자체 문제입니다.
