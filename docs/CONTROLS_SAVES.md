# 조작 설정 · 자동 저장 · 백업 복구

alpha.16부터 새로 변환한 검토된 XP·VX Ace 기본 스크립트 프로젝트와 전체 템플릿에서 제공합니다. 타이틀과 게임 메뉴의 **조작·저장**을 선택하세요. 기존 RGSS Input 상수와 저장 헤더, XP 4개/VXA 16개의 수동 슬롯은 유지합니다.

## 조작 설정

- 키보드·XInput 패드의 방향/달리기/취소/확인/보조 X·Y·Z/이전/다음 12개 동작을 설정합니다. 키보드와 패드 설정은 별도입니다.
- 항목을 선택한 뒤 10초 안에 새 버튼을 누릅니다. Esc는 취소합니다. 중복 할당, F12, IME 처리 키는 거부하며 방향·확인·취소의 키보드 할당은 비울 수 없습니다.
- 설정 화면에서 Enter/Esc는 항상 확인/뒤로 가기로 사용할 수 있습니다. 기본값 복원도 제공합니다. 기존 Input의 Shift/Ctrl/Alt/F5~F9 계약은 그대로입니다.
- 마지막으로 누른 장치에 따라 설정 화면의 확인/취소 안내가 바뀝니다. 연결된 첫 XInput 패드를 사용하며 빈 슬롯은 1초 간격으로 검색합니다. 왼쪽 스틱 방향은 기존 16000 기준을 유지합니다.
- 진동 켜기/끄기와 300ms 테스트를 제공합니다. 전투 중 아군 HP 감소 시 짧게 진동합니다. 진동은 지정 시간이 지나거나 포커스 상실·브라우저 포커스·F12·종료 시 정지합니다. Input.update가 없는 Graphics 갱신에서도 Windows 타이머가 정지 요청을 처리합니다.
- 설정은 `Saves/Lunetile/controls.json`입니다. 손상·초과 크기·잘못된 구조는 기본값으로 실행하고 원래 파일을 보존합니다. 사용자가 새 설정을 저장할 때만 교체합니다.

```ruby
controls = Lunetile::Controls
controls.bind(:confirm, keys: [86], pad: :rt) # V / RT (다른 동작과 중복 불가)
controls.binding(:confirm)                  # [[86], :rt]
controls.device                            # :keyboard / :gamepad
controls.prompt(:confirm)                   # 현재 장치의 버튼 이름
controls.connected?                        # 현재 선택한 XInput 패드
controls.rumble(0.3, 0.5, 150)              # 왼쪽/오른쪽 0..1, 0..5000ms
controls.rumble(0, 0, 0)                    # 정지
controls.reset                             # 기본값 저장/적용
```

설정·입력 API는 게임 스레드에서 사용하세요. XInput 이외의 패드, 장치 고유 햅틱, 물리 버튼 배열 자동 판별은 포함하지 않습니다. `connected?`는 Input.update가 마지막으로 관측한 상태입니다. 진동 API의 true는 요청/정지 수락이며 물리 모터 작동의 증거가 아닙니다. 입력 차단·미연결 시 시작 요청은 false입니다.

## 자동 저장

기본값은 켜짐이며 설정 화면에서 바꿀 수 있습니다. 맵 초기화/이동 또는 전투 종료(패배 제외) 후 최소 1초가 지난 안전한 맵 상태에서 한 번 저장합니다. 안전 조건은 최대 초당 4번 확인하며 매 프레임 저장하지 않습니다.

저장 금지, 이동/점프/강제 이동, 대화, 맵 이벤트·병렬 이벤트·예약된 공통 이벤트 실행, 전송/전투/게임 오버 전환 중에는 기다립니다. 상시 병렬 이벤트가 있으면 다음 안전한 시점까지 자동 저장이 미뤄질 수 있습니다. 쓰기 실패 시 수동 저장을 유지하고 설정 화면에 실패를 표시합니다.

| 엔진 | 자동 저장 | 수동 저장 |
|---|---|---|
| XP | `Saves/RGSSXP/Autosave.rxdata` | 기존 `Save1`~`Save4.rxdata` |
| VX Ace | `Saves/LunetileVXA/Autosave.rvdata2` | 기존 `Save01`~`Save16.rvdata2` |

자동 저장 설정은 `Saves/Lunetile/comfort.json`입니다. 자동 저장은 수동 슬롯을 소비하지 않습니다. 맵 시작 시 자동 저장이 만들어질 수 있으므로 중요한 분기는 수동 슬롯에도 저장하세요.

## 백업과 복구

자동·수동 저장 각각에 직전의 정상 버전 3개를 `.bak1`(최신)~`.bak3`으로 보관합니다. 새 데이터와 이전 버전을 검사한 뒤 임시 파일에 쓰고 flush/fsync 후 교체합니다. 최종 교체가 실패해도 기존 현재 파일은 유지합니다. 손상된 이전 파일을 정상 백업 앞으로 밀어 넣지 않습니다. 여러 파일을 묶은 단일 트랜잭션이나 전원 차단 후의 파일시스템 복구를 보증하지는 않습니다.

**조작·저장 → 자동 저장 / 백업 불러오기**에서 자동 저장 또는 수동 백업을 선택하고 불러오기를 확인하세요. 손상된 파일은 오류를 표시하며 검사 실패로 게임 상태를 부분 교체하지 않습니다. 복구는 원본 파일에 덮어쓰지 않고 메모리로 불러오며, 직후 자동 저장도 실행하지 않습니다. 이후 정상 수동 저장으로 새 진행을 보관하세요.

`Saves/Import`의 원본 저장은 읽기 전용이며 백업 순환이나 자동 저장의 대상으로 사용하지 않습니다. 저장·백업·개인 설정은 배포 ZIP에 포함하지 않습니다.

## 기존 변환본 업데이트

새 메뉴와 자동 저장은 변환된 기본 스크립트의 설치 호출 및 새 VXA 저장 보조 코드가 함께 필요합니다. **이 기능 전체를 적용하려면 최신 변환기로 원본을 별도 새 폴더에 변환하세요.** 기존 변환본의 `Saves`는 먼저 별도로 보관하고, 같은 엔진의 새 변환본에 복사해 불러오기를 확인하세요. 개인 저장과 게임 데이터를 전체 템플릿으로 덮어쓰지 마세요.

DLL 교체 ZIP은 기존 기능의 런타임 업데이트용입니다. 기존 VXA 보조 스크립트에 DLL만 교체하면 새 메뉴·자동 저장·수동 백업이 모두 설치되는 것은 아닙니다. 사용자 수정 스크립트/MMO에 설치 호출을 임의로 넣지 마세요.

## 검증 명령과 범위

```powershell
python -X utf8 -B -m unittest discover -s tests -v
python -X utf8 -B scripts/test_runtime_comfort.py build/comfort-new-check
python -X utf8 -B scripts/verify_runtime.py build/comfort-release-new --mode release
```

기능 검사는 두 엔진의 실제 실행기에서 설정 검증/재실행, 백업 순환, 교체 실패 주입, 자동 저장 안전 조건, 손상 파일 거부, 복구와 상태 되돌리기를 확인합니다. 네이티브 probe는 키/패드 범위와 진동 만료·포커스 비활성 정지를 검사합니다. 연결된 실물 패드가 없는 검증은 진동 체감/실물 핫플러그 증거가 아니며 별도로 표시합니다. 전원 차단·장기 내구성·전체 게임·임의 플러그인 인증은 포함하지 않습니다.

`LunetileXInputProbe.dll`은 검사 프로세스 안에서만 XInput/전경 창 조회를 시험 장치로 바꾸는 도구입니다. 실제 런타임 DLL의 RT 매핑·장치 안내·모터 값·Graphics 갱신만으로 시간 만료·포커스 복귀 억제·F12·최종 종료 정지를 확인합니다. 드라이버를 설치하거나 물리 모터를 구동하지 않으며 게임 ZIP에 포함하지 않습니다. 이 기능 검사는 RTP 없이 CI에서도 실행합니다.
