# XP·VXA 배포 템플릿의 기본 스크립트 최적화

이번 변경은 템플릿 패키저에서만 적용합니다. 원본 `template-xp/`, `template-vxa/`와 일반 프로젝트 변환기, 기존 게임 및 MMO 패키지는 변경하지 않습니다. 기존 호환/타이밍 부트스트랩 뒤, 원본 Main 앞에 보조 코드를 넣습니다. XP 90개/VXA 126개 항목의 ID·이름·순서를 유지하며 Main 이외 항목은 기존 변환 결과와 원시 바이트가 같습니다.

기준/후보의 DLL은 동일한 파일입니다. 새 DLL을 빌드하지 않습니다.

- XP: `2e4093fb47a681b96399a09b5ce2d86544421a3cc89a6d4aa4b4d842af85cab1`
- VXA: `6b57754d6149eac9942963a81ec4293bd830e550b2fc0a754df3458251360bad`

## 구현

캐릭터 표시에서 소스 Rect를 입력이 바뀔 때만 설정하고 현재 Sprite 값이 이미 같으면 속성 설정을 생략합니다. 고정된 Lunetile DLL의 내부 표시 값으로 비교하며, 변경할 때는 기존 setter 검증을 사용합니다. Sprite 갱신의 기존 liveness 검사와 기본 효과 처리를 유지합니다. VXA 위치 계산은 같은 호출 안의 screen_x/y 중복을 제거합니다. XP 화면 좌표는 실제 위치·스크롤·캐릭터/맵 식별자와 점프 상태를 확인하고 재사용합니다. Z·효과·애니메이션 주기는 유지합니다. 그래픽 변경에는 Rect 캐시를 무효화하여 타일에서 같은 캐릭터 이미지로 돌아와도 즉시 반영합니다.

이동의 min/max 임시 배열은 스칼라 비교로 바꿉니다. 같은 값에서는 원래 첫 피연산자를 선택하여 Integer/Float 타입을 유지합니다. 기존 120Hz 이동 잔여값과 타이밍 배율은 바꾸지 않습니다.

이벤트 32개 이상인 활성 맵에 실제 점유 좌표만 인덱싱합니다. 목록 순위를 보관하여 같은 좌표에서도 기존 순서를 유지합니다. 논리 좌표 변경 지점에서 즉시 인덱스를 이동합니다. 판정 조건과 through/우선순위는 현재 값을 읽습니다. VXA 공개 조회는 새 배열을 반환하고 XP check_event의 미발견 Array 반환도 보존합니다. 비정수 좌표·비표준 객체/컬렉션은 기존 검색을 사용합니다. 표준 이벤트/경로/조건/변수의 Script 실행 전에 최적화를 해제하며 프로세스 재실행까지 유지합니다. 직접적인 임의 플러그인의 상태 조작은 인증하지 않습니다.

캐시는 저장 대상 Game_* 객체 밖에 두고 맵 설정·불러오기·장면 재진입·F12에서 폐기합니다. XP 갱신 루프의 스냅샷과 VXA each_value 갱신 순서는 변경하지 않습니다. 게임 로직·화면 밖 이벤트·병렬 처리·Fiber 갱신을 생략하지 않습니다.

VXA 저장 미리보기는 한 refresh 동안 검증 결과를 재사용해 16슬롯의 본문 읽기를 32→16회로 줄입니다. 다음 refresh는 다시 읽으며 정상·손상·빈·Import 처리와 전체 본문 검증을 유지합니다. 예외에도 참조를 해제합니다. 저장 형식과 XP 저장 창은 변경하지 않습니다.

## 측정과 완료 기준

```powershell
python -X utf8 -B scripts/benchmark_stock_scripts.py BASELINE CANDIDATE NEW_OUTPUT --profile cpu
python -X utf8 -B scripts/benchmark_stock_scripts.py BASELINE CANDIDATE NEW_OUTPUT --profile render
python -X utf8 -B scripts/benchmark_stock_scripts.py BASELINE CANDIDATE NEW_OUTPUT --profile save
```

두 입력 폴더에 xp/vxa 하위 프로젝트를 둡니다. CPU 기본값은 200회 워밍업 후 1,500회×3쌍 교대 비교입니다. 짧은 진단은 formal=false로 표시합니다. 300/1,000개 정지 캐릭터 평균 30%·할당 40%, 분산 조회 평균 70%·VXA 조회 할당 25%, 자율 이동 평균 30%, VXA 300이벤트/16슬롯 미리보기 평균 30% 이상 감소를 요구합니다. 움직임/스크롤/효과·밀집 조회는 평균/p95 증가 10% 이하입니다. 작은 장면은 평균 +max(10%,0.05ms), p95 +max(10%,0.1ms) 이내입니다.

NPC 이동 CPU 장면에는 통행 가능한 바닥을 사용합니다. 원본 VXA 물 맵에서 이동이 막히는 조건도 별도 회귀 부하로 보존합니다. 조회 전용/표시 전용/이동 부하는 분리하며 RNG와 상태 동등성은 별도 정확성 검사에서 확인합니다.

정식 기본 맵은 1280×720에서 정지/왕복 이동 각 30초×3쌍과 40/60FPS 각 10초를 검사합니다. 전체 Scene 갱신에서 네이티브 스케줄러 대기만 빼므로 논리·표시 동기화·명령 생성·해석·제출·Present를 포함합니다. 이전 렌더 구간 합계도 별도 기록합니다. GPU는 유효한 고유 시퀀스만 기록하고 CPU 합계에 더하지 않습니다. 평균/p95 증가 5% 이하, 출력 ≥118FPS·로직 119–121Hz·누락 ≤2%가 기준입니다. 출력은 DXGI Present 제출이며 물리 스캔아웃은 아닙니다.

원본·개인 파일과 비교 소스/템플릿을 먼저 보존합니다. 검사에는 31/32 경계, 조회 반환값/순서, 연속 이동·강제 경로·점프·루프/경계·페이지·소거·through·저장/불러오기·Script 복귀, 캐릭터 및 Bitmap/타일 교체·효과·스크롤·GC·해상도/클리핑의 상태와 전체 RGBA를 포함합니다. Python 전체, 기본 장면·속도·F12·창/전체 화면과 격리 MMO 회귀를 확인합니다.

성능 미달과 진단 시나리오 실패를 보존합니다. 정식 결과와 분리하고 재시도 성공으로 최초 실패를 지우지 않습니다. 엔진별 전체 템플릿/진단 ZIP만 생성하며 DLL 교체 ZIP·기존 게임 패치·원격 푸시/릴리스는 만들지 않습니다. 새 폴더에서 압축 해제해 원본 RGSS DLL 없이 실행하고 CRC·DLL 동일성·소스/데이터 보존을 검사합니다.

하드웨어 성능은 로컬 측정 범위입니다. 임의 플러그인, 물리 IME 조합/스캔아웃과 장기 내구성은 인증하지 않습니다.

## 보존한 실패와 판정
