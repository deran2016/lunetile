# 회원가입·로그인과 캐릭터 선택

서버 EXE·Lunetile.dll·Scripts.rxdata를 함께 갱신하는 v11 배포입니다. 기존 캐릭터 schema 3, 인벤토리·장비·스킬·퀵슬롯은 보존합니다.

## 시작하기

1. Start Server.cmd → Start Client.cmd를 실행합니다.
2. 처음이면 회원가입을 누르고 ID·비밀번호·비밀번호 확인을 입력합니다. ID는 소문자/숫자/밑줄 3~20자, 비밀번호는 영문·숫자·기호 12~128자입니다. Tab으로 칸을 이동하고 Enter로 확인할 수 있습니다.
3. 캐릭터 선택 화면의 빈 칸에서 캐릭터 생성을 누릅니다. 새 창에서 닉네임을 입력하고 미리보기 3종 중 하나를 클릭해 선택한 뒤 생성합니다. 계정당 3칸입니다. 닉네임은 한글 완성형·영문·숫자 2~12자이며 공백·기호는 사용할 수 없습니다. 영문 대소문자는 같은 이름으로 취급하며 기존 캐릭터·다른 계정·생성 중인 이름까지 서버가 중복 검사합니다. 중복이면 입력을 유지하므로 이름을 수정해 다시 생성하세요. 한글 마지막 음절이 조합 중일 때 Enter 또는 생성 버튼으로 전체 이름을 반영합니다.
4. 모험 시작을 누르면 선택한 캐릭터로 입장합니다. 모두 초보자로 시작하고 기존 레벨 조건에 따라 게임 안에서 전직합니다.
5. 캐릭터를 바꾸려면 게임 종료 후 다시 로그인합니다. 선택 화면의 로그아웃은 로그인 화면으로 돌아갑니다. 비밀번호는 클라이언트에 기억하지 않으며 마지막 ID만 기억합니다.

한글 채팅은 마지막 음절이 조합 중이어도 **Enter 한 번으로 확정하고 전송**합니다. Esc는 전송 없이 취소합니다. 일반 RGSS Input과 기존 GUI key_trigger 계약은 유지하고 채팅은 새 UIInput.text_submit?를 사용합니다.

## 이전 캐릭터 연결

기존 `client.json`의 profile이 가리키는 ClientProfile 파일을 그대로 둡니다. 새 계정으로 로그인한 뒤 캐릭터 선택창의 **이전 프로필 캐릭터 연결**을 누르면 기존 ID·토큰을 서버가 검증해 빈 칸에 연결합니다. 현재 프로필의 캐릭터 하나를 연결하며 다른 이전 프로필은 client.json의 profile을 해당 파일명으로 바꿔 같은 과정을 반복합니다. 연결은 계정당 3칸까지만 가능합니다.

다른 계정이 이미 연결한 캐릭터는 가져올 수 없습니다. 계정에 연결한 뒤에는 이전 토큰만으로 직접 입장할 수 없으며 ID·비밀번호 로그인이 필요합니다. 기존 플레이어·인벤토리·프로필 파일은 덮어쓰거나 지우지 않습니다.

캐릭터별 새 접속·퀵슬롯 파일은 `ClientProfile/c_<캐릭터ID>.json`과 `.quicks.json`입니다. 연결한 기존 캐릭터의 퀵슬롯은 새 파일이 없을 때만 검증하여 복사하고 원본은 보존합니다. 신규 캐릭터에는 다른 캐릭터의 배치를 복사하지 않습니다.

## 서버 파일과 복구

- accounts/ID.json: 소금값·PBKDF2-HMAC-SHA256 해시·반복 횟수·3칸의 소유권/초기 생성 기록입니다. 비밀번호 원문은 저장하지 않습니다.
- players/캐릭터ID.json: 기존 캐릭터 schema 3과 게임 상태입니다.
- transactions/: 승인된 게임 변경의 WAL과 체크포인트입니다.

Windows CNG로 600,000회 PBKDF2를 수행하며 동시에 최대 2개만 처리합니다. 이 작업은 월드 처리 스레드 밖에서 실행합니다. 같은 계정의 중복 접속, 다른 계정의 소유권 요청, 잘못된 ID·비밀번호·슬롯·외형을 거부합니다. 인증 실패 시 비밀번호나 요청 본문을 로그에 남기지 않습니다.

캐릭터 생성은 소유권 예약 파일 저장 → 초기 플레이어 WAL 동기화 → 완료 표시 저장 순서입니다. 중간 종료 시 pending 생성만 같은 ID로 마칩니다. 완료된 캐릭터 파일이 사라진 경우 새 캐릭터로 초기화하지 않고 백업 복원을 요구합니다. ID·token·pending·characters를 수동으로 수정하지 마세요.

정상 종료한 뒤 **accounts·players·transactions를 같은 시점에 함께 백업**하고 클라이언트 ClientProfile도 보관하세요. 강제 종료 후에는 `--recover-only`가 성공한 뒤 편집합니다. 이번 갱신 전 파일은 server/backups/pre-character-create에 별도 보존합니다. 이전 자동 이름·4번째 외형을 가진 캐릭터도 그대로 유지하며 이름이나 외형을 강제로 바꾸지 않습니다. 공개 ZIP에는 계정·플레이어·프로필·저널·백업을 넣지 않습니다.

통신은 기존 로컬/신뢰 LAN용 평문 TCP입니다. 이 서버에서만 사용할 비밀번호를 사용하세요. 인터넷 공개 서비스용 TLS·인증 운영·비밀번호 찾기/재설정은 제공하지 않습니다.

구현 기준: Microsoft [ImmGetVirtualKey](https://learn.microsoft.com/en-us/windows/win32/api/imm/nf-imm-immgetvirtualkey), [BCryptDeriveKeyPBKDF2](https://learn.microsoft.com/en-us/windows/win32/api/bcrypt/nf-bcrypt-bcryptderivekeypbkdf2). 실제 Windows IME 조합 검사와 자동 시나리오는 VALIDATION.md에 구분합니다.
