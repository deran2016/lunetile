# XP MMORPG 설계

변환된 XP 프로젝트를 복사하고 Scripts.rxdata의 기존 네 기능 스크립트에 HUD·Chat·Combat을 추가합니다. Main은 초기화와 실행 호출만 맡습니다. 클라이언트는 입력·렌더링, Rust 서버는 위치·전투·아이템·보상·성장의 주인입니다. 원본 마을을 보존하고 예제용 사냥터 세 개와 보스 맵을 추가합니다. MMO_Windows·MMO_Equipment·MMO_Skills가 추가 기능 창을 맡습니다.

## 서버와 저장

단일 world-owner가 전체 1,024개·연결별 32개의 제한된 변경 대기열을 순서대로 처리합니다. 최대 5ms/64개 작업 묶음의 게임 규칙을 임시 상태에서 계산하고, durable-wal 작업자의 동기화 성공 후에만 공개 스냅샷·ACK·이벤트를 갱신합니다. 연결별 수신/송신 스레드는 이 월드에 직접 변경 명령을 실행하지 않습니다. poll과 preview는 마지막 확정 월드의 짧은 잠금을 쓰고, 응답 직렬화·소켓 쓰기는 잠금 밖에서 수행합니다. 송신 큐 32개 포화 또는 2초 쓰기 제한은 해당 연결을 종료합니다.

게임 규칙의 save_player와 다중 플레이어 저널 호출은 월드 처리 스레드의 캡처 범위에서 완전한 변경 후 이미지로 모읍니다. 기존 단위 검사·오프라인 이전은 기존 원자 JSON 저장을 사용합니다. WAL은 순번·길이·CRC32·끝 표식을 가진 트랜잭션이며 거래·다중 처치 보상은 하나의 플레이어 배열로 기록합니다. 저장 실패 시 임시 상태를 공개하지 않고 변경 처리를 종료해 복구를 요구합니다.

json-checkpoint 작업자는 약 1초 간격으로 최신 변경을 플레이어별로 합칩니다. 최대 8개의 제한된 파일 작업이 기존 임시 파일 sync·Windows 원자 교체·백업 절차를 사용합니다. 모든 JSON과 체크포인트 순번의 저장이 성공한 후에만 WAL 작업자가 반영 구간을 원자적으로 정리합니다. 체크포인트 실패 시 WAL을 보존하고 다음 주기에 재시도하며 WAL이 64MiB에 도달하면 추가 변경을 차단합니다. 느린 저장장치에서는 1초 작업 간격보다 실제 반영이 늦어질 수 있습니다.

시작 시 기존 pending.json을 먼저 복구하고 새 WAL의 유효한 전체 기록을 재생합니다. 불완전한 마지막 기록은 승인된 기록으로 취급하지 않고, 완전한 기록의 체크섬·순번 오류는 복구를 중단합니다. 재적용은 최종 상태 덮어쓰기와 체크포인트로 멱등성을 유지합니다. Ctrl+C 종료는 큐와 체크포인트를 정리하며 --recover-only는 포트를 열지 않고 복구·검증 후 종료합니다. 저널에는 비밀 토큰이 포함되며 체크포인트와 함께 비공개 저장 데이터로 관리합니다. players와 transactions를 함께 백업합니다.

성장·스킬·몬스터·아이템·NPC·맵·서버 설정은 data/*.json이고 플레이어 schema 3과 기존 ID·토큰·위치·가방·보상·장비 기록을 유지합니다. 같은 폴더의 두 서버는 잠금으로 차단합니다. 프로세스 종료 복구와 Windows 파일 오류는 검사하지만 저장장치 고장·실제 전원 차단 보장은 별도입니다. 성능 측정과 운영 명령은 PERFORMANCE.md에 기록합니다.

## 판정과 성장

기존 방향별 통행 비트·NPC 충돌과 4방향 5칸/초 이동을 유지합니다. 공격은 스킬 ID·2/4/6/8 방향만 받아 전방 부채꼴의 모든 생존 몬스터를 서버가 고릅니다. 전방 투영 거리 f가 0~range이며 옆 거리의 절댓값이 f 이하인 칸입니다. 대각선 시야는 supercover 방식으로 정확한 모서리의 양쪽 통로를 모두 검사합니다. 허공에도 1회 MP·쿨다운이 적용됩니다. 실제 피해만 참여량에 합산합니다. 살아 있고 같은 맵에 접속한 참여자에게 피해 비율로 경험치를 나누고 정수 잔여는 소수점 내림차순·ID 오름차순으로 배정합니다.

한 번의 광역 공격은 시작 능력치로 모든 피해를 계산하고 몬스터별 경험치 분배를 플레이어별로 합산한 다음 저널 한 건으로 저장합니다. 저장 실패 시 몬스터 HP·피해 참여·모션 이벤트·쿨다운을 반영하지 않습니다. 부분 파일 커밋이 남은 경우 서버가 중지되어 시작 시 복구합니다.

투척 스킬은 기존 attack 요청의 스킬 ID·방향을 사용합니다. 서버가 최대 3칸의 직선 경로를 검사해 착탄점과 시야가 열린 주변 3×3칸을 확정하고 MP 저장 성공 후 투척을 예약합니다. 발사 시의 공격력·스킬 단계와 착탄점은 고정하고, 발사 후 1000ms가 지난 첫 100ms tick에서 현재 범위 안 몬스터에 피해를 줍니다. 비행 시간 400ms는 이 1000ms에 포함합니다. 한 번만 차감한 MP·쿨다운과 지연 폭발을 구분하며, 처치 보상은 기존 다중 대상 저널을 재사용합니다. 폭발 직전의 현재 플레이어 상태에 보상을 합쳐 투척 후 이동·장비 변경을 되돌리지 않습니다. 투척 후 사망·맵 이동·접속 종료에도 폭발하며 경험치 지급 자격은 기존 생존·접속·같은 맵 조건을 따릅니다. 동시 투척은 서버 전체 64개까지입니다. 투척물은 몬스터처럼 세션 메모리이며 재시작 후 복구하지 않습니다. 발사 시 저장한 MP는 되돌리지 않습니다.

기본 규칙은 README 표기와 JSON에 있습니다. 레벨업은 경험치 이월·다중 상승·최고 레벨 MAX를 지원하고 HP·MP를 회복합니다. 사망 후 2초 귀환은 일반 이동과 구분한 `respawn` 이벤트로 전송합니다. 클라이언트가 보간 대기열을 비우고 귀환 좌표에 즉시 배치합니다. 몬스터 추적은 통과 가능한 4방향 후보 중 거리를 줄이는 칸을 고르는 간단한 규칙이며 복잡한 미로의 완전 경로 탐색은 제공하지 않습니다.

## 프로토콜 v11

welcome.catalog에 items·skills·progression·services·particle_presets를 한 번 전송합니다. MMO_Network는 매 접속마다 이를 새로 받아 이후 state와 합쳐 기존 GUI의 데이터 구조를 유지합니다. 서버는 맵별 공개 뷰와 개인 뷰를 공유 참조로 획득하고 잠금 밖에서 응답을 구성합니다. 연결별로 이미 보낸 이벤트와 다른 플레이어의 경로 순번은 다시 전송하지 않으며 본인 보정 이력은 유지합니다. 이벤트 보관 범위를 넘긴 연결은 재접속을 요구합니다.

프레임은 u32 big-endian 길이 + UTF-8 JSON, 요청 16KiB·응답 256KiB 제한입니다. register/login에 protocol:11을 요구합니다. poll, preview(origin,epoch,elapsed,parts:[{step,direction,ms}],moving,direction), move(seq,origin,epoch,parts:[{direction,ms}]), talk(npc_id), use(item_id), chat(text), attack(skill_id,direction)을 지원합니다. 이동 seq는 연결마다 1부터 연속 증가하며 중복·건너뛴 순번은 판정하지 않습니다. 각 state의 move_ack(seq,accepted)는 마지막 처리 이동과 성공 여부를 전달합니다. 벽·NPC 충돌은 그 직전 위치에 멈춘 성공 응답이며, 속도 예산 초과·시작 좌표/귀환 세대 불일치·저장 실패도 해당 순번을 처리한 것으로 응답하며 성공은 저장 완료 후에만 표시합니다. 순번은 플레이어 파일에 저장하지 않습니다. 요청 필드·종류·길이·범위를 검사합니다. 연결 제한 시간·초당 요청 제한도 유지합니다.

state는 본인 HP·MP·레벨·경험치·다음 경험치·공격력·가방·쿨다운과 같은 맵의 플레이어·NPC·몬스터·맵 이름, 아이템·스킬 정의, 채팅·이벤트를 담습니다. 다른 계정의 토큰·가방·보상 기록을 노출하지 않습니다. 승인된 공격·피해·경험치·레벨업·대화·귀환에는 단조 증가 순번을 붙이고 클라이언트가 중복을 제거합니다. 최근 이벤트 256개·채팅 8개는 세션 메모리에만 보관하므로 장시간 연결 정지 후 놓친 알림을 재생하지는 않습니다. 저장된 실제 상태는 재접속으로 복원합니다.

v8부터 사용한 attack 이벤트는 투척일 때 projectile(id/source/position/target/cells/icon/flight_ms/delay_ms/radius/elapsed_ms)을 포함합니다. 같은 맵 state.projectiles에도 활성 투척물을 보내 늦게 접속한 관찰자가 남은 비행·장판을 표시합니다. 공개 스냅샷에도 활성 목록을 복사합니다. explosion 이벤트는 원래 투척 ID·착탄점·반경을 담고 기존 damage 이벤트가 실제 피해·처치를 전달합니다. 클라이언트는 이벤트 순번과 투척 ID로 중복을 막고 경과 시간이 뒤로 돌아가지 않게 합니다. 장판은 서버 폭발/상태 제거까지 유지하며 100ms 서버 tick과 통신 주기만큼 표시가 늦을 수 있습니다.

이동은 클라이언트 로직 갱신마다 최신 방향으로 즉시 예측합니다. 1ms에 1/200칸(초당 5칸)을 이동하고 한 프레임의 방향은 하나만 사용합니다. 칸 중간에서도 회전·반전·키 해제가 즉시 적용됩니다. 요청은 최대 200ms·32개 방향 구간으로 묶고, 서버가 시작 좌표와 귀환 세대, 시간 예산을 검사한 뒤 1ms 구간마다 통행 경계를 검사합니다. 현재·다음 칸의 통행 비트와 NPC 점유를 모두 검사하여 벽·지도 밖·막힌 모서리를 통과하지 못합니다. 충돌하면 경계 직전까지 이동합니다.

좌표는 1/1000칸 정수로 계산합니다. 기존 Player.position은 가장 가까운 타일 좌표이며 기본값 0인 offset_x/offset_y를 더해 정확한 위치를 저장합니다. 기존 schema 2 계정은 원본 .pre-v7.bak을 보존한 뒤 성장 확장 필드를 포함한 schema 3으로 원자 이전합니다. NPC·몬스터·맵 JSON의 타일 좌표와 기존 전투 판정은 유지합니다. state의 motion(x,y,epoch,path)은 실제 좌표, 귀환 세대, 순번이 있는 최근 방향 구간 끝점 64개를 전달합니다. 관찰자는 300ms 버퍼 없이 수신 즉시 순번을 중복 제거하여 실제 모서리대로 이동합니다. preview는 최근 확정 위치에서 이어지는 최대 600ms의 로직 프레임 경로와 누적 이동 시간을 전달합니다. 서버는 시작점·세대·프레임 순번·이전 표시 경로의 연결·시간 예산·충돌을 검사하고 메모리의 relay만 갱신합니다. 플레이어 파일·확정 위치·전투 위치·move_ack는 변경하지 않습니다. 성공한 preview는 응답을 보내지 않고, 실패는 기존 state.notice로 알립니다. poll은 최대 30Hz이며 preview도 최대 30Hz에 저장 직전 마지막 경로 마감을 추가합니다. 연결당 요청 상한은 초당 96개입니다. relay는 x/y·epoch·step·direction·moving·최근 모서리/끝점 32개·검사된 lead_x/lead_y를 전달합니다. 직선 중간점을 합쳐 패킷 크기를 줄입니다. 서버가 벽과 NPC를 검사한 최대 60ms 앞까지만 예측하고, 150ms 이상 새 경로가 없으면 추가 예측을 중단합니다. 정지·회전 시 지나친 예측은 실제 모서리로 축별 복원합니다. 작은 끝점 사이의 남은 이동 예산을 이어 받아 반올림 정지를 없애며 평균 초당 5칸을 유지합니다. 저장 실패 시 검증했던 원래 경로를 역순으로 전달하고 귀환/접속 종료 시 표시 경로를 비웁니다. 응답 순번·경로 순번·귀환 세대는 세션 메모리에만 보관합니다. 본인의 표시 이동에는 이 보간 여유를 적용하지 않습니다. TCP_NODELAY로 작은 클라이언트 패킷의 Nagle 대기도 제거하며 네이티브 TCP 작업의 5ms 폴링으로 수신 대기 중 새 송신 지연을 제한합니다.

state.navigation은 확정 위치 주변 7×7칸(가장자리는 잘림)의 원본 통행 비트·좌상단·맵 ID를 담습니다. 클라이언트는 같은 통행 규칙과 NPC 위치를 사용하며 범위 밖 경계를 예측하지 않습니다. 서버에 아직 승인되지 않은 시간은 전송 전 구간을 포함하여 최대 600ms(3칸)입니다. 승인된 이동은 재생하지 않습니다. 불일치하면 새 예측을 중단하고 전송된 요청의 응답을 모두 받은 후, 예측 경로를 역으로 돌아가 서버의 실제 승인 경로를 따라 보정합니다. 일반 보정은 축별·같은 속도로 처리하고 카메라는 표시 좌표를 따릅니다. 귀환 이벤트는 즉시 경로를 비우며 이전 귀환 세대로 전송된 요청은 서버가 거부합니다.

방향 예약은 마지막 새 누름 하나만 250ms 보관하고 새 누름으로 교체합니다. 일반 이동에는 타일 중심 대기나 200ms 입력 예약이 없습니다. 응답 한도에 걸렸을 때만 예약 수명 안에서 다시 시도합니다. UIInput.direction4/direction_trigger는 Windows 메시지 순서로 겹친 키와 같은 갱신 전의 짧은 누름을 판별하고 자동 반복을 제외합니다. 게임패드는 기존 Input.dir4의 변화로 보완합니다. 공격 조준도 같은 방향을 사용합니다. UI 차단·포커스 상실·사망/귀환·보정은 예약을 비우고, 이미 실제로 이동한 전송 전 구간만 서버에 마감 전송합니다. 공격·NPC 대화 전에도 해당 구간을 먼저 보내어 서버 판정 위치를 맞춥니다.

## GUI와 입력

fire_wave/light_wave/water_wave는 공통(beginner 조건이 모든 직업과 일치) 레벨 1·최대 5단계·단계당 SP 1의 독립 액티브 정의입니다. 기존 skills.json의 전투 설정과 progression.json의 습득 규칙만 확장하며 클라이언트는 첫 페이지의 공통 스킬 행·습득 버튼·드래그·개별 binding을 그대로 사용합니다. 화염/물은 fan, 빛은 line이며 각각 fire/light/water를 cast/hit에 연결합니다. 새 스킬 추가 때문에 SP를 보충하거나 슬롯을 자동 교체하지 않습니다. 서버 전투 스킬 정의 상한은 64개이며 기존 개별 필드 검증과 초과 거부를 유지합니다.

MMO_Particles는 서버 data/particles.json의 레이어 정의를 상태에서 받아 검증·캐시합니다. 스킬의 particles.cast/hit/explosion을 승인된 attack/damage/explosion 이벤트에 프리셋 ID로 넣고 기존 이벤트 순번으로 한 번만 재생합니다. 같은 순번을 난수 시드로 쓰되 표시 시간은 각 클라이언트의 수신 시점을 기준으로 합니다. 전투·경험치·저장 트랜잭션과 플레이어 schema 3, 명령 프로토콜 v11은 유지합니다.

여섯 32px 도형 bitmap과 레이어별 32단계 색을 재사용하고, 필요할 때 만든 Sprite를 최대 160개 풀로 보관합니다. 빈 풀이 미리 160개 표시 객체를 등록하지 않아 비전투 정렬 비용을 줄입니다. 분사기 24개·분사기당 한 로직 갱신에 생성 32개로 제한하며 남는 요청은 생략합니다. 속도·중력은 실제 경과 시간의 해석식으로 계산하고 크기·색·불투명도·회전을 수명에 따라 바꿉니다. 생성 순간부터 올바른 표시 좌표를 적용하여 원점에 한 프레임 깜박이지 않습니다. 입자는 월드 좌표에 남고 카메라 오프셋만 표시 때 뺍니다. 맵 전환은 효과만 비우고 장면 종료는 풀 Sprite·전용 bitmap을 해제합니다. 공유 RTP 캐시는 건드리지 않습니다. 스키마·범위와 누락된 프리셋 참조는 서버 시작 시 거부합니다. 기본 배포와 기존 파일의 설정 병합 방법은 PARTICLES.md에 기록합니다.

Player.public의 선택적 weapon 필드는 장착한 무기의 정의 ID 또는 null만 보냅니다. 장비 인스턴스·인벤토리·토큰은 공개하지 않습니다. v9에서도 유지하는 표시용 필드로 플레이어 JSON/schema 3과 명령은 그대로이며 이전 클라이언트는 이 필드를 무시합니다. 새 클라이언트는 캐시된 state.progression.equipment에서 아이콘을 찾아 CombatCharacter의 별도 손 무기 Sprite에 캐시합니다. 방향·걷기 패턴·공격 이벤트 시간에 따라 위치·각도·앞뒤 순서를 갱신하고 부모의 불투명도·표시 상태를 따릅니다. 해제·맵 변경·장면 종료 때 Sprite만 해제하고 공유 RTP 아이콘은 해제하지 않습니다. 기존 공격 효과의 별도 무기 Sprite를 제거하여 이중 표시를 막았습니다.

포탈 엔티티는 클라이언트에서 portal=true와 Lunetile_Portal 캐릭터칩을 사용합니다. CombatCharacter는 실제 PNG의 정수 분할 크기 313×313을 사용해 첫 행의 네 프레임을 5Hz로 재생하며 72px 셀에 축소하고 발 위치를 고정합니다. 파일은 제작 결과 그대로 보관하며 프레임 정렬·투명도·반복과 실제 화면을 검사합니다. 공유 캐릭터 캐시를 사용하므로 포탈마다 대형 bitmap을 만들지 않습니다. 포탈의 서버 위치·목적지·레벨 제한·통행과 원본 맵은 변경하지 않습니다.

스킬 목록 행의 기존 선택 콜백에서 배운 액티브 스킬만 드래그 후보로 잡습니다. 퀵슬롯도 누르는 순간에는 사용하지 않고 후보만 잡으며 6px 이상 움직이면 드래그로 전환합니다. 이동이 없으면 같은 슬롯에서 버튼을 놓을 때 한 번 사용합니다. 눌렀다 이동·해제한 이벤트가 한 로직 갱신에 들어와도 UIInput.mouse_press_position의 시작점과 현재 위치를 구분합니다. 드래그 중 마우스 경로는 아래 패널 클릭·몬스터 선택에 전달하지 않으며 키보드 이동·스킬은 기존 규칙을 따릅니다.

스킬 목록에서 놓으면 대상 슬롯을 교체하고, 슬롯에서 놓으면 두 binding을 한 번의 save_quickslot_layout으로 교환합니다. 빈 칸은 null과 교환합니다. 원본 binding이 누를 때와 달라졌으면 취소하고, 바깥·덮인 슬롯·원래 칸에 놓는 드래그는 변경하거나 사용하지 않습니다. 파일 저장 실패도 기존 배열과 파일을 유지합니다. 취소는 Esc·우클릭·포커스/텍스트 입력 전환·창 열기/닫기·사망·맵 변경·장면 종료에 연결합니다. 커서 Sprite는 공유 RTP 아이콘을 사용하고 대상 테두리의 40×40 bitmap만 소유합니다. 놓기·취소·종료 때 Sprite와 테두리 bitmap을 해제하며 공유 아이콘은 해제하지 않습니다. 드래그가 없을 때는 기존 캐시와 입력 경로를 유지합니다.

퀵슬롯 키는 Z/X/V/F/1/2/3/4입니다. 스킬 창에서 배운 액티브 스킬을 선택하고 해당 키 버튼을 누르면 그 칸에 등록합니다. 슬롯 우클릭은 해제, 기본 배치 버튼은 기본 공격·기존 X 스킬·HP/MP 물약을 복원합니다. 패널은 우측 상단 (1048,16,216,100), 미니맵은 y=124부터이며 그리기·클릭은 동일한 40×40 사각형 8개를 사용합니다. 선택한 스킬이 등록된 버튼에는 체크 표시를 캐시합니다. 일반 창이 열린 상태에서도 키와 퀵슬롯을 사용합니다. 채팅·이름 입력·사망·포커스 상실은 막고 등록 변경 후에는 누르고 있던 키를 다시 눌러야 반복합니다.

배치는 서버 계정과 분리된 ClientProfile/<프로필>.quicks.json의 {id,slots}에 저장합니다. slots는 8개이며 null/skill:<id>/item:<id>만 허용합니다. 크기 4096바이트·형식·ID와 캐릭터 일치를 검사하고 다른 계정의 배치는 이어받지 않습니다. 파일 flush/fsync·원자 이름 교체 성공 후 메모리에 반영하므로 실패하면 이전 배치가 유지됩니다. 기존 프로필 토큰·플레이어 JSON·프로토콜 v11은 바꾸지 않습니다. 설정이 없는 기존 프로필은 서버 quick_skill을 X로 계속 사용하며 배치를 직접 저장한 뒤부터 로컬 설정이 우선합니다. 여러 슬롯의 같은 스킬은 ID별 동일 쿨다운을 공유하고 동시 스킬 키는 오른쪽 슬롯 우선, 물약은 새 누름에 한 번씩 처리합니다. 슬롯은 skill_id/item_id 요청으로 실행하므로 서버의 습득·MP·사거리·충돌·저장 판정은 동일합니다. 배치의 자동 기기 간 동기화는 제공하지 않습니다.

1280×720 기준으로 하단 48px HUD에 이름·레벨, HP·MP·EXP를 배치하고 우측 상단에 40×40px 퀵슬롯 여덟 개를 4×2로 배치합니다. 미니맵은 퀵슬롯 아래, 드롭업 메뉴 버튼은 우측 하단에 배치합니다. 퀵슬롯 간격은 4px이며 그리기와 클릭 판정이 같은 사각형을 사용합니다. 좌우·하단 여백은 16px, 채팅은 높이 190px를 유지해 HUD 위에 배치합니다. 채팅 배경은 비포커스 알파 144·포커스 208이고 HUD의 z는 필드 이름표·피해 숫자보다 높습니다. 다른 패널의 반투명 배경은 유지합니다. 가방은 격자와 페이지·설명·사용 버튼을 제공하고 가방·정보 창은 제목줄로 끌어 이동합니다. 패널 배경 bitmap을 캐시하고 표시 값의 signature가 바뀔 때 다시 그립니다. 필드 이름표·피해 숫자 위치는 매 로직 갱신에 캐릭터의 실제 좌표를 따릅니다. 공격 이벤트는 원점·방향·모션/시간·범위·아이콘을, 피해 이벤트는 위치·실제 피해·효과·처치 여부를 담습니다. 사라진 몬스터도 위치와 짧은 잔상으로 효과를 표시합니다.

미니맵은 192×106px 안에 전체 지도를 비율 유지하여 축소합니다. 공유 RTP 캐시의 실제 타일셋·오토타일과 맵 레이어를 읽으며 런타임의 RGSSXP::AUTOTILE_QUARTERS 및 타일 우선순위 정렬을 재사용합니다. 작은 결과 bitmap에 직접 합성하고 오토타일 조립에만 32×32px 임시 stamp를 사용하므로 전체 지도 크기의 bitmap은 만들지 않습니다. 오토타일은 첫 프레임으로 고정합니다. 맵 ID·크기·데이터 객체·타일셋이 같으면 지형을 재사용하고, 100ms HUD 갱신에서 캐릭터의 표시 좌표를 같은 축척의 마커로 변환합니다. 맵 변경과 장면 종료 시 미니맵 소유 bitmap만 해제하며 공유 RTP bitmap은 해제하지 않습니다. 원본 맵은 수정하지 않습니다.

효과 5종의 8프레임씩을 장면 시작 시 캐시하고 실제 시간으로 재생합니다. 투척은 공유 RTP 아이콘을 포물선 좌표로 이동·회전하고 지상에 서버가 허용한 칸만 붉게 표시합니다. 장판 소유 bitmap은 폭발·맵 변경·종료 때 해제하고 공유 RTP 아이콘은 해제하지 않습니다. 캐릭터 자세는 별도 CombatCharacter 렌더링에만 적용하여 이동 보간을 건드리지 않습니다. Z/X 반복은 서버 쿨다운과 로컬 예약으로 요청을 제한하고 늦어진 요청을 몰아 보내지 않습니다. 채팅·이름 입력·포커스 상실 뒤 물리 키 해제를 확인해야 재개합니다. 기존 Win32API의 창 활성 상태와 키 조회를 사용하므로 새 DLL은 필요하지 않습니다.

Lunetile::UIInput은 기존 RGSS Input과 별도로 실제 키·마우스·휠·UTF-8 확정/조합 문자열을 제공합니다. 렌더러와 같은 letterbox 역변환을 사용해 창 크기·DPI 변화에서 게임 좌표를 구합니다. Windows IMM 결과를 직접 소비하여 DefWindowProc에 의한 WM_CHAR 중복을 막고, IME 확정 직후 전달되는 Enter가 전송까지 실행되지 않게 합니다. 채팅을 닫으면 IME를 잠시 닫아 게임 단축키가 한글 조합으로 소비되지 않게 합니다. 이전 RGSS 게임이 새 API를 사용하지 않으면 IME 상태를 바꾸지 않습니다.

신뢰 PC·사설 LAN용 평문 TCP입니다. 로컬 32명 부하와 선택적 운영 지표를 검사하며 실제 두 PC LAN·인터넷은 별도입니다. 공개 서비스의 TLS·계정 복구·관리 권한, 대규모 월드·인스턴스·경매장·우편·펫·제작·길드전은 포함하지 않습니다.


## 확장 소유권과 협동

progression.json은 장비 정의·스킬 단계·강화, services.json은 퀘스트·포털·상점·드롭을 관리합니다. 클라이언트는 progress(action,key), service(action,key,amount), social(action,key,amount,text,revision)을 요청합니다. 서버가 레벨·직업·소유·위치·수량·재화·선행 조건을 검증합니다. 상대의 전체 인벤토리는 공개하지 않으며 거래 제시 물품만 공개합니다. 장비는 개별 ID를 유지하므로 강화 단계가 거래·창고에서도 보존됩니다. 전체 계정에서 중복 장비 ID를 거부합니다.

단일·다중 플레이어 변경 모두 새 WAL을 사용하고, 여러 플레이어의 처치 보상·거래·길드 변경은 한 트랜잭션으로 묶습니다. 드롭 확률은 서버 Windows 난수로 결정하며 저장에 성공한 뒤 알림을 보냅니다. 한도 때문에 받지 못한 드롭도 알립니다. 파티·초대·미완료 거래는 세션 메모리, 길드·퀘스트·재화·장비·창고·스킬은 플레이어 파일에 저장합니다. 파티원 보상도 동일 처치 저널에 포함합니다.

포털은 서버가 인접 거리와 입장 레벨을 검사하고 위치 저장 후 이동 세대를 올립니다. 클라이언트는 새 맵의 Spriteset·캐릭터·미니맵을 교체하고 이전 이동 예측을 버립니다. 생성 맵은 복사된 XP 프로젝트에만 추가합니다. 원본 Map001은 바이트 그대로 유지합니다. 신규 지형과 서버 통행은 world_layouts.json의 동일 배치에서 생성했습니다.

패널은 캐시한 배경·미니맵 지형·불투명 전경 세 Sprite 층으로 구성합니다. 마우스가 가장 위 창에 있을 때 배경만 강조하고 채팅 입력·드래그는 포커스를 유지합니다. 표시값이 바뀔 때만 텍스트·슬롯을 갱신합니다. 일반 팝업의 열기·닫기·드래그·클릭은 이동/전투 로직을 중단하지 않습니다. 텍스트 입력·포커스 상실·사망만 차단하며 방향키를 인벤토리 선택에 사용하지 않습니다. 채팅 스크롤은 실제 줄 수를 기준으로 계산하고 새 메시지의 줄 수만큼 오프셋을 늘려 과거 기록의 읽기 위치를 보존합니다. 이름 테두리는 변경 시에만 여덟 방향으로 그려 캐시합니다. 서버 피해 이벤트 중 source가 본인인 살아 있는 몬스터를 상단 HP 대상으로 골라 클릭 없이 표시합니다.

## 계정과 캐릭터 선택

MMO_Entry가 로그인과 캐릭터 선택을 처리하고, 선택한 Connection을 MMO_UI에 전달합니다. 가입·로그인은 연결 처리 스레드의 Windows CNG PBKDF2를 사용하며 월드 스레드를 막지 않습니다. accounts 파일의 3칸 소유권과 players schema 3을 분리하고 생성 예약·초기 플레이어 WAL·완료 표시로 복구합니다. 완료된 플레이어 파일 누락은 초기화하지 않습니다. 이전 프로필은 토큰을 검증해 연결하고 원본은 보존합니다. 자세한 형식과 범위는 ACCOUNTS.md에 있습니다.

신규 생성 요청은 character_create(slot,appearance,name)이며 외형은 0~2입니다. 닉네임 2~12자의 한글 완성형·영문·숫자를 허용하고 ASCII 대소문자 동일 키로 기존/예약 이름을 검사합니다. 계정 잠금 안에서 이름을 예약하여 동시 생성의 중복을 차단하며 월드 확정에서도 다시 검사합니다. 기존 이름과 외형은 소급 변경하지 않습니다.
