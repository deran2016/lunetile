# Lunetile XP MMORPG 예제

변환 완료한 XP 프로젝트를 별도로 복사한 Windows 예제입니다. Windows x64 Rust 서버, x86 Lunetile 클라이언트, UTF-8 JSON 파일 DB로 구성합니다. 1280×720 MMORPG HUD, 한글 채팅, 공동 사냥, 레벨 1~30 성장, 4계열 1·2차 전직, 퀘스트·장비·강화·상점·창고·거래·파티·길드를 실제 서버 상태에 연결했습니다. 원본 XP 프로젝트는 수정하지 않습니다.

## 바로 실행하기

1. `Start Server.cmd`를 실행하고 서버 창을 열어 둡니다.
2. `Start Client.cmd`에서 회원가입 또는 로그인한 뒤 3칸 선택창의 빈 칸에서 닉네임을 입력하고 이미지 3종 중 하나를 골라 캐릭터를 만듭니다.
3. 마을 안내인 옆에서 Space로 1회 보상(HP 물약 3개·배지)을 받습니다.
4. 몬스터 쪽을 바라보고 Z 또는 X를 누르고 있으면 전방을 광역 공격합니다. 시작 HP 70/100은 물약을 바로 시험하기 위한 값입니다.
5. Esc 메뉴의 게임 종료로 나갑니다. 재실행하면 로그인 후 캐릭터를 선택합니다. 기존 캐릭터 연결·계정 파일·복구는 [ACCOUNTS.md](ACCOUNTS.md)를 참고하세요.

클라이언트에는 XP Standard RTP와 Microsoft Visual C++ x86 런타임, 서버에는 Visual C++ x64 런타임이 필요합니다. RTP를 배포판에 복사하지 않습니다. 서버에는 Rust나 별도 DB 설치가 필요하지 않습니다. XP 로컬 세이브는 온라인 저장에 사용하지 않습니다.

가방·스킬·장비·대화·메뉴 등 일반 창을 열거나 끌어도 방향키 이동과 Z/X·퀵슬롯 전투를 계속합니다. 방향키는 가방 선택 대신 캐릭터 이동에 쓰고 Enter는 채팅을 엽니다. 채팅·길드 이름 입력 중에는 이동·공격 단축키를 막습니다. 한글 조합 중에도 Enter 한 번으로 확정하고 전송합니다. Ctrl+V로 문자열을 붙일 수도 있습니다. 채팅은 최대 100자입니다. 가방·정보·기능 창은 제목줄로 이동하며 화면 밖으로 벗어나지 않습니다. 뒤 창의 보이는 부분을 클릭하면 앞으로 올라옵니다. HUD는 화면 가장자리에 고정되며 패널 배경을 캐시합니다.

하단 HUD는 높이 48px로 이름·레벨과 HP·MP·경험치를 표시합니다. 40×40px 퀵슬롯 8개는 우측 상단의 4×2 배치에, 미니맵은 그 아래에 배치합니다. 우측 하단 메뉴 버튼을 누르면 기능 메뉴가 위로 펼쳐지며 항목 선택·바깥 클릭·Esc로 닫힙니다. 이름·캐릭터·NPC·몬스터 이름표는 검은 테두리로 표시합니다. 채팅은 휠·드래그 가능한 스크롤바로 최대 100개 메시지를 탐색하며, 과거 기록을 보는 중 새 메시지가 와도 읽던 위치를 유지합니다. 화면 좌우·하단 여백은 16px입니다. 높이 190px의 채팅창은 HUD 바로 위에 놓이며 반투명합니다. 채팅·미니맵 배경과 미니맵 지형은 비포커스 알파 144, 마우스를 올리면 208입니다. 이동 가능한 창은 비포커스 144, 포커스 238이며 글자·아이콘·마커는 항상 불투명합니다. 채팅 입력과 창 드래그 중에는 포커스를 유지합니다. 미니맵은 실제 타일셋·오토타일·세 레이어로 전체 지도를 축소한 이미지입니다. 기존 40×23칸 잔디 지도는 그대로 유지하며 오토타일은 첫 프레임만 표시합니다. 지형은 맵마다 한 번 생성하고 캐릭터 마커는 화면에 표시되는 위치를 따라 갱신합니다.

방향키를 바꾸면 칸 중간에서도 즉시 직각 회전·반전하고, 키를 놓으면 그 자리에서 멈춥니다. 4방향·초당 5칸 속도는 유지합니다. 화면 이동은 즉시 예측하며 서버가 실제 경로의 벽·방향별 통행·NPC 충돌을 검증합니다. 미승인 이동 시간은 최대 600ms(3칸)입니다. 방향 구간을 최대 200ms 단위로 묶어 저장합니다. 다른 접속자에게는 서버가 같은 충돌·시간 예산으로 검사한 표시 경로를 최대 초당 30회 먼저 전달하고, 수신 즉시 표시합니다. 300ms 시작 버퍼는 없습니다. 서버가 통행을 검사한 최대 60ms 앞 위치까지만 짧게 예측하며, 정지·회전·저장 실패 때 실제 경로를 따라 맞춥니다. 네트워크·서버 처리 지연 자체는 남습니다. 본인의 이동과 방향 전환은 입력을 읽은 프레임에 표시합니다.

온라인 장면은 창이 비활성화되어도 통신과 월드 표시를 계속 갱신합니다. 게임 키·마우스·IME 입력은 전경 창에서만 받습니다.

## 사냥과 성장

초보자로 시작하여 레벨 5에 전사·마법사·궁수·도적 중 한 계열을 고르고 레벨 20에 같은 계열의 2차로 전직합니다. 마을 1개, 사냥터 3개, 보스 맵 1개와 몬스터 5종·13마리가 있습니다. 마을의 마법 포탈 옆에서 Space로 지역을 이동합니다. 사냥터 입장은 레벨 1/8/16, 보스는 25부터입니다. 기본 공격과 공용 마력 일격을 제공합니다. 기본 공격은 전방 1줄·폭 3칸·600ms, 마력 일격은 전방 3줄·폭 3/5/7칸·MP 10·1.2초입니다. 같은 칸도 포함하고 뒤쪽은 제외합니다. 서버가 부채꼴 범위·벽·NPC·대각선 모서리·MP·쿨다운·생존 여부를 판정합니다. 허공에도 사용되며 MP와 쿨다운은 사용당 한 번 적용합니다.

기본 공격은 몸 기울임·무기 회전·검 궤적(기본 240ms), 스킬은 시전 자세·발광·마력 파동(360ms)을 표시합니다. 적중 시 몬스터 점멸·충돌 섬광·피해 숫자와 처치 잔상이 나옵니다. 서버 승인 후 양쪽 클라이언트에서 재생하며 실제 좌표와 카메라는 바꾸지 않습니다. 퀵슬롯 클릭은 한 번만 사용합니다. 채팅·이름 입력·게임 창 전환으로 중단되면 키를 놓았다가 다시 눌러야 재개합니다.

공용 스킬 **폭탄 투척**은 K → 폭탄 투척 → `습득 / 강화`(SP 1) → `X 슬롯 등록`으로 사용합니다. 모든 직업이 배울 수 있으며 기존에 SP를 모두 썼다면 레벨업으로 SP를 얻으세요. 바라보는 방향으로 최대 3칸을 400ms 동안 포물선으로 날아가고, 발사 1초 후 착탄 지점 주변 한 칸씩 **3×3 범위**에서 폭발합니다. 비행 중부터 붉은 장판으로 실제 피해 범위를 표시합니다. MP 10·재사용 2초이며 1단계 피해는 공격력+20, 최대 5단계까지 단계당 +5입니다. 벽·NPC·맵 끝에서는 투척 거리가 짧아지고 가려진 칸은 장판과 피해에서 제외됩니다. 서버가 폭발 순간 범위에 있는 몬스터를 판정하므로 움직여 피하거나 새로 범위에 들어올 수 있습니다. 사용 중인 투척물은 서버 재시작 시 사라지며 이미 소비한 MP는 유지됩니다.

레벨 1은 HP 100·MP 50·공격력 10이며 레벨마다 +20·+10·+2입니다. 다음 레벨 경험치는 현재 레벨×50, 최고 레벨은 30(MAX)입니다. 레벨업 시 남은 경험치를 이월하고 HP·MP를 회복합니다. 비전투 3초 후 MP를 초당 5 회복합니다. 사망 시 2초 후 시작 위치로 귀환하여 전량 회복합니다.

몬스터는 HP 30·공격력 5·경험치 10, 4칸 인식·400ms 이동·인접 1초 공격·5초 재생성입니다. 출현점에서 6칸을 벗어나면 복귀합니다. 상단 몬스터 체력은 서버가 확인한 본인 타격으로 자동 표시합니다. 여러 마리를 맞히면 현재 대상이 같은 타격에 포함될 때 유지하고, 그렇지 않으면 가까운 생존 몬스터를 표시합니다. 다른 접속자의 공격은 선택을 바꾸지 않으며 대상이 죽거나 맵이 바뀌면 숨깁니다.

처치 경험치는 같은 맵에 접속한 살아 있는 참여자의 실제 피해 비율로 분배합니다. 나머지는 소수점 잔여 내림차순, 동률이면 ID 오름차순으로 지급하여 총량을 맞춥니다.

## 모험 진행과 핵심 시스템

v9부터 서버는 변경 내용을 저널에 동기 저장한 뒤 승인하고, 플레이어 JSON은 약 1초마다 반영합니다. **파일 편집 전에는 서버를 정상 종료하거나 `--recover-only`를 실행하세요.** 저장 경로·복구·백업·계측과 성능 결과 해석은 [PERFORMANCE.md](PERFORMANCE.md)를 참고하세요.

**새 속성 스킬:** K 스킬 창 첫 페이지의 **화염 분출·빛의 파동·물보라**를 선택해 `습득 / 강화`로 배우고, 아이콘이나 행을 원하는 퀵슬롯으로 드래그하세요. 예: X=화염, V=빛, F=물. 모든 직업이 레벨 1부터 단계당 SP 1로 배울 수 있으며 최대 5단계입니다. 세 스킬을 모두 1단계 배우려면 SP 3이 필요합니다. 기존 스킬·SP·슬롯 배치는 유지합니다. MP·범위·재사용 시간은 [PARTICLES.md](PARTICLES.md)에 정리했습니다.

화염·빛·물 파티클 효과를 추가했습니다. 마력 일격은 빛, 폭탄 폭발은 불꽃·불씨·연기, 마법사 스킬은 물방울·물결을 표시합니다. `server/data/particles.json`에서 색·수명·중력·크기·분사 방향을 편집하고 `skills.json`의 `particles`로 시전·피격·폭발에 연결합니다. 설정 예제와 제한은 [PARTICLES.md](PARTICLES.md)를 참고하세요. 운영 설정에 새 필드가 없을 때만 기본 연결을 보충하며 이전 skills.json은 `server/backups/pre-particles/data/`에 보관합니다.

무기 부위를 장착하면 해당 장비 정의의 `icon`이 캐릭터 손 위치에 표시됩니다. 네 방향에 맞춰 위치와 앞뒤 순서를 바꾸고 걷기·공격·시전 모션을 따라갑니다. 장착 해제·교체는 본인과 다른 접속자 화면에 함께 반영하며 공격 때 별도의 떠 있는 무기 아이콘을 중복 표시하지 않습니다. 기존 캐릭터 시트와 장비 저장 형식은 유지합니다.

기존 빛 기둥 포탈은 자체 제작한 푸른빛·보랏빛 마법문 캐릭터칩으로 교체했습니다. 네 프레임이 반복되며 이동 목적지·입장 레벨·서버 충돌은 그대로입니다. 배포 파일은 `client/Graphics/Characters/Lunetile_Portal.png`, 제작 방식과 프롬프트는 배포본의 ART_ASSETS.md에 있습니다. XP/RTP 원본 파일은 변경하지 않습니다.

**드래그 등록:** K 창에서 배운 액티브 스킬의 아이콘이나 목록 행을 퀵슬롯으로 끌어 놓습니다. **슬롯 이동:** 퀵슬롯을 다른 퀵슬롯으로 끌면 두 칸을 교환하고, 빈 칸이면 해당 칸으로 이동합니다. 기본 공격·물약도 같은 방식으로 옮길 수 있습니다. 커서에 반투명 아이콘이 따라오고 놓을 수 있는 칸에 테두리를 표시합니다. 바깥·가려진 슬롯에 놓거나 Esc·우클릭으로 취소하면 원래 배치가 유지됩니다. 포커스 상실·입력창 전환·창 닫기·사망·맵 변경도 진행 중인 드래그를 취소합니다. 드래그는 스킬을 사용하지 않으며 짧은 클릭만 버튼을 놓을 때 한 번 사용합니다. 변경된 배치는 즉시 저장되어 재접속 후에도 유지됩니다.

K 스킬 창에서 배운 액티브 스킬을 선택한 뒤 **Z/X/V/F/1/2/3/4 버튼** 중 원하는 칸을 누릅니다. 예를 들어 마력 일격은 X, 폭탄 투척은 V에 등록하면 두 키로 따로 사용할 수 있습니다. 같은 스킬을 여러 칸에 등록해도 쿨다운은 공유합니다. 오른쪽 끝에 있는 스킬 슬롯이 동시 입력 우선이며 기본 배치의 X도 Z보다 우선합니다. 퀵슬롯 우클릭으로 한 칸을 비우고, 스킬 창의 `기본 배치`로 기본 공격·기존 X 스킬·물약을 복원합니다. 등록할 때 이미 누르고 있던 키는 놓았다 다시 눌러야 실행합니다.

배치는 `client/ClientProfile/<프로필>.quicks.json`에 캐릭터 ID와 함께 원자적으로 저장합니다. 재실행·재접속 후 유지하며 기존 토큰 파일은 변경하지 않습니다. 다른 PC로 배치를 옮기려면 해당 프로필의 두 JSON 파일을 함께 복사하세요. 서버의 계정·인벤토리·프로토콜 v11은 유지하고 스킬 습득·MP·사거리·쿨다운은 계속 서버가 검증합니다. 배우지 않은 스킬·패시브는 등록하지 못하며 서버 정의에서 없어진 스킬은 빈 칸처럼 동작합니다.

처음에는 I로 가방을 열어 지급된 여섯 부위 장비를 장착하세요. K에서 SP 1을 써서 마력 일격을 배우고 X 버튼을 눌러 등록합니다. 레벨마다 SP 1을 받으며 액티브·패시브는 각각 최대 5단계입니다. 기존 계정은 마력 일격 1단계를 유지하고 해당 SP 1을 사용한 상태로 이전됩니다. 전사·도적은 부채꼴, 마법사·궁수는 직선 관통 스킬이며 계열마다 1차·2차 액티브와 패시브 하나씩을 제공합니다. 스킬 습득·장비 조건은 서버가 검증합니다.

Q의 퀘스트 10개는 선행 퀘스트 순서대로 마을에서 수락·보상 수령합니다. 사냥으로 경험치·재화·강화석·장비를 얻습니다. 장비는 무기·방패·투구·갑옷·신발·장신구이며 개별 ID와 강화 단계를 보존합니다. 가방·창고 합계 256개까지 보유합니다. 강화는 최대 +5, 비용 100/200/400/800/1600, 성공률 100/90/75/60/45%이며 강화석 1개를 씁니다. 실패해도 장비와 단계는 보존됩니다.

상점·창고·강화·전직은 마을에서 이용합니다. 창고는 캐릭터별이며 재화·소모품·장비를 보관합니다. 장착한 장비는 해제한 뒤 보관·판매·거래하세요. 수량 버튼은 소모품과 재화에 적용하고 장비는 하나씩 처리합니다.

파티는 최대 4명입니다. P에서 만들기 → 근처 상대 선택 → 초대, 상대가 30초 안에 수락합니다. 살아 있고 몬스터에서 8칸 이내인 같은 맵의 파티원에게 경험치를 균등 분배하고 퀘스트 처치를 공유합니다. 기여자별 피해 비율 보상을 나눈 뒤 정수 잔여를 ID 순으로 배정해 경험치 총량을 보존합니다. 재화·드롭은 실제 피해가 가장 큰 참여자(동률 ID 순)가 받습니다. 파티는 접속 중에만 유지하며 파티장 종료 시 남은 첫 멤버가 이어받습니다.

길드는 최대 20명이고 생성 비용은 500입니다. G에서 이름을 입력해 만들고 근처 상대를 초대합니다. 멤버·이름은 서버를 다시 켜도 유지됩니다. 길드장만 추방·해산할 수 있습니다. 거래는 T에서 근처 상대의 수락 후 재화·아이템·장비를 제시하고 양쪽이 같은 내용을 확인해야 성립합니다. 내용 변경 시 동의를 취소하며 120초 만료·이동으로 거리 초과·사망·접속 종료 시 거래를 취소합니다. 완료 전에는 물품을 이동하지 않고 마지막에 소유권·수량을 다시 검사합니다.

보스는 고대 수호자(HP 5000, 공격 45, 경험치 2000) 한 종류이며 공동 사냥이 가능합니다. 처치 후 60초에 재생성합니다. 전용 다단계 패턴이나 인스턴스 던전은 없는 소규모 필드 보스입니다.

레벨을 편집할 때 `exp`는 다음 레벨 미만으로 설정하고 `progress.skill_points`와 습득한 스킬 단계 합계가 레벨과 같게 맞추세요. 장비 인스턴스 ID를 복제하지 마세요. v7부터 schema 3으로 저장하며 v11에서도 유지합니다. 이전 계정에는 시작 장비를 한 번만 지급하고 ID·토큰·현재 능력치·위치·인벤토리·NPC 수령 기록을 보존합니다. 최대 HP·MP는 성장 정의와 레벨로 다시 계산하며 현재 HP·MP는 새 최대치 이내에서 보존합니다. 기존 v1 계정은 원본을 `.v1.bak`으로 보관한 뒤 레벨 1·경험치 0·MP 50으로 자동 이전합니다. ID·토큰·위치·현재 HP·가방·보상 기록은 유지합니다.

이전 v7 갱신 전 계정·운영 설정은 `server/backups/pre-v7/`에도 보존했습니다. 이 폴더는 토큰을 포함하므로 공유하지 마세요.

서버를 정상 종료하고 `accounts`·`players`·`transactions` 전체, 클라이언트 `ClientProfile`을 함께 백업하세요. 비정상 종료했다면 먼저 `--recover-only`가 성공한 뒤 편집하세요. 토큰이 있으므로 Git·공유 ZIP에 넣지 마세요. `active.wal`·`checkpoint.json`·이전 `pending.json`은 임의로 삭제·수정하지 마세요. 시작 시 미완료 지급을 재적용하고 완료된 파일은 건너뜁니다. 저장 실패가 나면 원인을 해결하고 서버를 다시 실행하세요. `.bak`은 직전 1회 복구용이며 전체 백업을 대신하지 않습니다.

`skills.json`의 `range`는 전방 깊이(1~10), `motion`은 `slash`/`magic`/`throw`, `motion_ms`는 80~2000ms, `hit_effect`는 `spark`/`magic`입니다. 투척은 `motion: "throw"`와 `projectile: {"flight_ms": 400, "delay_ms": 1000, "radius": 1}`을 함께 설정하고 `progression.json`의 같은 스킬 `shape`도 `throw`로 맞춥니다. `flight_ms`는 100~2000, `delay_ms`는 비행 시간 이상~10000이며 발사부터 폭발까지의 시간입니다. `radius`는 1~3이며 1이면 3×3입니다. 이전 정의에서 새 표시 필드가 빠져 있으면 기본 공격은 slash·240·spark, burst는 magic·360·magic으로 읽습니다. 투척 정의는 motion을 생략하면 throw로 읽습니다. 수치는 직접 편집할 수 있고 캐릭터 원본 이미지는 바꾸지 않습니다.

이전 투척 갱신 당시 설정은 `server/backups/pre-grenade/data/`에 보관했습니다. 이번 v11 갱신은 기존 스킬 정의를 바꾸지 않습니다. 플레이어 schema 3·계정·가방·접속 프로필은 유지합니다.

## 두 클라이언트와 연결 설정

같은 PC에서는 `client`를 별도로 복사하고 두 번째 폴더의 `ClientProfile`을 제외하거나 `client.json`의 `profile`을 `player2`로 바꾸세요. 각 창에서 서로 다른 계정으로 로그인하세요. 같은 계정의 동시 접속은 거부합니다.

기본 주소는 `127.0.0.1:4100`입니다. 신뢰 LAN에서는 서버 `bind`를 `0.0.0.0:4100`, 클라이언트 `host`를 서버의 사설 IPv4로 설정합니다. 방화벽은 개인 네트워크의 해당 EXE/포트에 한정하세요. 실제 두 PC LAN은 이번 검증 범위에 포함하지 않습니다. 통신은 평문 TCP이며 인터넷 공개 운영에는 TLS·인증 운영·운영 방어가 추가로 필요합니다.

프로토콜은 **v11**입니다. Rust 서버 EXE·Lunetile.dll·Scripts.rxdata를 함께 갱신하세요. 이전 DLL의 direction4/direction_trigger와 text_submit API도 필요하며 구형 DLL·프로토콜 불일치는 업데이트 안내를 표시합니다. 기존 프로필과 플레이어 파일은 지우지 마세요.

## 소스 빌드와 구성

Windows Rust MSVC x64, VS2022 C++ 도구·SDK, Python 3.12, 빌드된 x86 런타임과 Ruby helper, 이미 변환된 UTF-8 XP 프로젝트가 필요합니다. 먼저 저장소의 `scripts/build_runtime.ps1`로 런타임을 빌드하세요. 새 GUI API가 없는 이전 DLL로는 실행하지 못합니다.

Git에는 서버 DB를 포함하지 않습니다. 빌드·Rust 테스트 전에 배포본의 `server/data/` 또는 별도로 보관한 DB를 로컬 `example/server/data/`에 준비하세요. 필요한 파일은 `server.json`, `maps.json`, `npcs.json`, `items.json`, `growth.json`, `skills.json`, `monsters.json`, `progression.json`, `services.json`, `particles.json`, `world_layouts.json`입니다. Python 검사 중 이 DB에 의존하는 항목은 파일이 없으면 명시적으로 건너뜁니다.

`example/server/data/`·계정·캐릭터·저널·백업, `ClientProfile/`·`Saves/`, Rust `target/`와 배포 `output/`는 `.gitignore`로 제외합니다. DB를 강제로 Git에 추가하지 말고, 정상 종료 또는 복구 완료 후 별도로 백업하세요. 소스·잠금 파일·라이선스·테스트·문서와 자체 제작 포털 이미지만 버전 관리합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File example/build.ps1 `
  -ConvertedProject "E:\path\to\converted-xp" -Output "NEW_OUTPUT"
```

기본 런타임은 `build/runtime-native/bin/Release/Lunetile.dll`이며 원본 변환 프로젝트의 DLL을 덮어쓰지 않고 출력에 복사합니다. 기존 출력 경로는 거부합니다. XP 이벤트가 있는 시작 맵은 먼저 서버 기능으로 옮겨야 합니다. 이 확장 예제 생성기는 제공된 시작 맵의 구조를 검사하며 다른 구조의 프로젝트는 거부합니다. 별도 프로젝트에 적용하려면 포털·지형·통행 정의를 먼저 맞추세요.

| MMO_Equipment / MMO_Skills | 장비 슬롯 / 스킬 습득·등록 |
| MMO_Particles | 화염·빛·물 레이어, 시간 기반 입자 물리·색·감쇠·Sprite 풀 |
| MMO_Entry | 회원가입·로그인·3칸 캐릭터 선택·외형·이전 프로필 연결 |
| Main | 변환 초기화와 LunetileMMO.run 호출 |

제공 템플릿은 기존 90개에 12개를 추가한 총 102개 엔트리입니다. 기존 MMO 엔트리 ID·상대 순서와 Main을 유지하고 Main 직전에 MMO_Entry를 추가합니다. 원본 XP 기능별 스크립트를 보존하며 외부 Ruby 파일을 로드하지 않습니다. 소스는 `example/client/*.rb`입니다.

최종 실행 폴더는 `example/output/LunetileMMO-Windows/`, ZIP과 SHA-256 파일은 같은 상위 폴더입니다. 로컬 최종 폴더에는 기존 계정과 프로필을 보존하며 ZIP에는 개인 데이터를 넣지 않습니다. `SHA256SUMS.json`은 배포 파일 해시, `build-info.json`은 입력·DLL·서버 해시를 기록합니다.

설계는 [DESIGN.md](DESIGN.md), 검증은 [VALIDATION.md](VALIDATION.md), 입력 API는 저장소의 `docs/UI_INPUT.md`를 참고하세요.

플레이어의 `position`은 해당 타일 좌표이며 `offset_x`·`offset_y`는 타일 중심으로부터 1/1000칸 단위의 위치입니다(-500~499). 기존 파일에 없으면 0으로 읽습니다. 좌표를 직접 옮겨 타일 중심에 배치하려면 두 offset을 0으로 설정하세요. 계정 ID·토큰·인벤토리·보상 수령 기록은 수정할 필요가 없습니다.
