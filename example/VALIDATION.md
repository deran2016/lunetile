# v11 닉네임 입력·중복 방지·이미지 선택 검증

검증일: 2026-10-25. Windows x64 Rust 서버, 기존 x86 DLL, 프로토콜 v11입니다. 증거는 build/mmo-final-verification/character-create/에 기록합니다. 이전 v10 계정·실제 Windows IME 검사는 accounts-ime/와 validation-before.md에 보존합니다.

## 변경

- 캐릭터 생성 화면에서 닉네임을 입력하고 RTP 이미지 3종을 미리 보고 선택합니다. 한글 완성형·영문·숫자 2~12자이며 영문 대소문자를 구분하지 않습니다.
- 서버가 기존 플레이어·계정·미완료 생성 예약의 이름을 검사하며, 다른 계정의 동시 생성도 하나만 허용합니다. 월드 확정 시 재검사하고 확정된 이름 충돌은 예약을 되돌립니다. 실패하면 창의 이름·이미지를 유지해 재입력합니다.
- 한글 조합 중 Enter와 생성 버튼은 조합 문자열을 함께 반영합니다. 생성·취소·로그인 화면 전환은 기능별 MMO_Entry에 구현하며 Main은 유지합니다.
- 기존 자동 이름과 4번째 이미지 캐릭터도 보존합니다. 계정 schema 1·플레이어 schema 3·월드 WAL 형식·네이티브 DLL API는 그대로입니다.

## 검증 결과

- Python 전체 157개 통과: 닉네임 조합 문자열 포함·이미지 선택 요청·중복 재시도·성공/취소·로그인·개인 프로필 보존과 기존 회귀 검사입니다.
- Rust 전체 89개 통과: 닉네임 경계·문자 종류·기존/예약 이름·영문 대소문자·동시 생성·이름 충돌 예약 해제·세 이미지 복구 및 기존 계정/월드/WAL 검사입니다. 네 번째 기존 이미지의 계정 연결·재시작·파일 보존도 검사합니다.
- TCP 통합 5개 시나리오 통과: 직접 지정한 한글 이름·선택 이미지·기존 이름 중복·형식 오류·동시 생성·비밀번호·소유권·강제 종료 후 복구입니다.
- 실제 Windows 클라이언트 두 개에서 생성창·3종 미리보기·이미지 클릭·중복 안내·이름 수정·입장을 확인했습니다. 격리된 더미 계정의 가입·로그인은 테스트 장면 내부 시나리오로 수행했으며 실제 사용자의 인증 창을 자동 조작하지 않았습니다.
- 첫 창에서 실제 한국어 IME 키 g/k/s/r/m/f로 입력했습니다. 버튼 클릭 직전 nickname='한', composition='글'이었으며 한 번 클릭해 '한글' 전체와 세 번째 이미지로 생성했습니다. 둘째 창에서는 문자열 주입으로 '한글'을 입력하고 Enter 한 번으로 중복 안내를 확인한 뒤 '둘'을 붙여 재생성했습니다. 문자열 주입과 실제 IME 조합을 구분합니다.
- 두 창의 공유 월드 상태에 ('한글', '003-Fighter03'), ('한글둘', '002-Fighter02')가 일치했습니다. 생성 전후 JSON·중복 화면 상태·월드 공개 캐릭터를 증거 폴더에 남겼습니다.
- 추가 TCP 6개/네이티브 두 클라이언트 회귀의 첫 실행에서 기존 MMO_Character의 '서버 이동 경로가 대각선입니다' 검사가 한 번 실패했습니다. 동일 바이너리·동일 시나리오를 재실행했을 때 이동·급회전·보상·물약·채팅·재접속이 통과했습니다. 이 간헐적 오류의 원인은 이번에 확정하지 않았으며 이동 안정성의 무조건 통과 증거로 사용하지 않습니다. 첫 실패 로그와 재실행 결과를 함께 보존합니다.

## 배포와 한계

서버 EXE와 Scripts.rxdata를 함께 갱신하고 구버전은 업데이트 안내를 표시합니다. 기존 개인 데이터·운영 설정·과거 백업 114개 파일과 캐릭터 3개를 해시로 보존하고 pre-character-create 백업을 남깁니다. 기존 102개 스크립트 ID·이름·순서를 유지하며 MMO_Network·MMO_Entry만 변경합니다. Main을 포함한 나머지 100개 원시 엔트리와 DLL은 동일합니다. 공개 ZIP에는 개인 데이터·계정·저널·백업·로그를 넣지 않으며 파일 해시와 ZIP CRC를 검사합니다.

실제 두 PC LAN·인터넷·장시간 부하는 이번에 재검사하지 않습니다. 기존 로컬/신뢰 LAN용 평문 TCP 통신의 한계는 동일합니다.
